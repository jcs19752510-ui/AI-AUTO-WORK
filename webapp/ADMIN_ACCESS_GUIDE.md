# 관리자 계정/접근 운영 가이드 (REQ-010)

이 문서는 이 사이트를 운영하는 관리자를 위한 가이드다. Wagtail 어드민 UI
자체(로그인 화면, 페이지 편집기 등)는 벤더가 기본 제공하는 화면이며
`04-ux-design.md`가 이미 밝힌 대로 새로 디자인하지 않는다 — 여기서는 **계정을
어떻게 만들고 관리하는지**만 다룬다.

## 1. 로그인 경로

- 운영자 로그인: `https://<도메인>/cms-admin/login/`
- 기본 경로(`/admin/`)가 아니라 `/cms-admin/`을 쓰는 이유는 자동화된 무차별
  대입 스캐너의 노출을 줄이기 위함이다(`03-system-design.md` §5.1, DEC-009).
  경로를 바꿨다고 로그인 자체가 더 안전해지는 것은 아니므로, 아래 2~4절의
  계정/비밀번호/레이트리밋 조치가 실제 방어선이다.
- `/django-admin/`(Django 기본 어드민)은 뉴스레터 구독자 삭제(REQ-016 파기절차,
  `subscribers/admin.py`) 등 극히 제한된 용도로만 쓰인다. 콘텐츠 운영은
  `/cms-admin/`만 사용한다.
- **두 로그인 경로 모두 4절의 레이트리밋으로 보호된다**(v1.3 재작업,
  DEF-09-01/DEC-039/DEC-040). 과거에는 `/cms-admin/login/`만 보호되고
  `/django-admin/login/`은 무방비였다 — 지금은 두 경로가 IP 기준 카운터를
  공유한다.

## 2. 최초 슈퍼유저 계정 생성 (Render 배포 환경)

**중요**: Render 공식 문서(render.com/docs/free "Other limitations",
2026-09-17 확인) 기준으로 **Free 웹 서비스는 Shell 접속(SSH/대시보드
Shell)과 one-off Job 실행을 지원하지 않는다.** 즉 배포된 인스턴스에
직접 들어가 대화형으로 `python manage.py createsuperuser`를 실행할 방법이
**없다**. 이 프로젝트는 v1을 Free 플랜으로 유지하기로 확정했으므로(DEC-011),
아래 절차를 대신 쓴다.

1. Render 대시보드 → 이 서비스의 Environment 탭에서 아래 세 값을 채운다.
   - `DJANGO_SUPERUSER_USERNAME`
   - `DJANGO_SUPERUSER_EMAIL`
   - `DJANGO_SUPERUSER_PASSWORD` (3절의 비밀번호 정책을 통과하는 값이어야
     실제로 계정이 만들어진다 — 통과하지 못하면 빌드 로그에 경고만 남고
     조용히 건너뛴다)
2. 배포를 실행(또는 재배포)한다. `build.sh`의 마지막 단계
   (`python manage.py ensure_superuser`, `core/management/commands/
   ensure_superuser.py`)가 **슈퍼유저가 아직 하나도 없을 때만** 이 값으로
   계정을 만든다.
3. 빌드 로그에서 `슈퍼유저 '...' 계정을 생성했습니다` 메시지를 확인한다.
4. **계정 생성이 확인되면 세 환경변수를 대시보드에서 지운다(강력 권장).**
   커맨드가 멱등(이미 슈퍼유저가 있으면 항상 건너뜀)하므로 지워도 기존
   계정에는 영향이 없다 — 평문 비밀번호를 환경변수에 계속 남겨두지 않기
   위한 조치다.
5. 이후 비밀번호를 바꾸고 싶으면 환경변수를 다시 쓰지 말고, `/cms-admin/`에
   로그인한 뒤 어드민 자체의 계정 설정(우측 상단 프로필 → 비밀번호 변경)을
   쓴다.

로컬 개발 환경(SQLite, `DEBUG=True`)에서는 위 제약이 없으므로 평소처럼
`python manage.py createsuperuser`를 대화형으로 실행하면 된다.

## 3. 비밀번호 정책

`config/settings/base.py`의 `AUTH_PASSWORD_VALIDATORS`(Django 기본 제공)가
모든 계정(슈퍼유저 포함)에 적용된다:

- 사용자 속성(아이디/이메일 등)과 너무 비슷한 비밀번호 금지
- 최소 길이(Django 기본 8자) 미만 금지
- 자주 쓰이는 비밀번호(사전 목록) 금지
- 숫자로만 이루어진 비밀번호 금지

이 정책은 Wagtail 어드민의 "비밀번호 변경" 폼과 `ensure_superuser` 커맨드
양쪽에 동일하게 적용된다(전자는 Django 폼이 자동으로, 후자는
`validate_password()`를 직접 호출해서 적용).

## 4. 로그인 무차별대입(brute-force) 방어

`/cms-admin/login/`(Wagtail)과 `/django-admin/login/`(Django 기본 관리자)
양쪽 모두, 같은 IP에서 15분 동안 합산 10회를 넘는 POST는 `429`로 즉시
거부된다(`core/admin_auth.py`의 `RateLimitedLoginView`/
`RateLimitedAdminLoginView`, WU-09 + v1.3 재작업). **두 경로는 같은 카운터를
공유한다** — 두 로그인 화면이 동일한 `auth_user` 슈퍼유저 계정을 공유하기
때문에, 카운터가 URL별로 분리되어 있으면 공격자가 시도를 두 URL에 나눠
예산을 사실상 2배(IP당 20회)로 늘릴 수 있다. 예를 들어 한 IP에서
`/cms-admin/login/`에 5회, `/django-admin/login/`에 5회 실패해도 합산
10회이므로 6번째 URL 어느 쪽에 보내든 11번째 시도는 `429`다.

계정(사용자명) 기준 잠금은 의도적으로 두지 않았다 — 공격자가 알려진 운영자
계정명으로 고의 실패를 반복해 정당한 1인 운영자 본인을 잠그는 것을 막기
위함이다.

이 제한은 Django `LocMemCache`(프로세스 로컬)를 쓴다. 이 사이트는 gunicorn
`--workers 1`로 고정되어 있어(`render.yaml`, DEC-026) 단일 프로세스 전제가
깨지지 않는 한 정상 동작한다. 워커를 늘릴 일이 생기면, 이 레이트리밋도
DEC-024/026이 이미 기록한 것과 같은 이유로 Redis 등 공유 저장소로 먼저
전환해야 한다.

## 5. 운영자/에디터 그룹 권한 범위

Wagtail 표준 그룹(Editors/Moderators)을 그대로 쓴다(신규 커스텀 그룹을
만들지 않음, DEC-009). 1인/소규모 운영(가정 A1) 전제이므로 v1은 실제로는
슈퍼유저 1명만 있는 것을 기본으로 상정하지만, 추가 편집자가 필요해지면
Wagtail 어드민(설정 → 그룹)에서 아래 그룹 중 하나에 배정한다.

| 그룹 | 페이지 권한(홈 이하 전체 트리에 상속) | 카테고리 스니펫 | 이미지 |
|---|---|---|---|
| Editors | 추가/수정(발행 권한 없음 — 발행은 Moderators 승인 필요) | 추가/수정/삭제 | 추가/수정 |
| Moderators | 추가/수정/발행 | 추가/수정/삭제 | 추가/수정 |
| (슈퍼유저) | 전체(위 제한 없음) | 전체 | 전체 |

- 페이지 권한은 Wagtail 코어가 루트 페이지에 부여한 것이 트리 전체(홈,
  블로그 글, 법적 페이지)에 자동 상속된다(Wagtail 표준 동작).
- 카테고리 스니펫 권한은 WU-09가 새로 발견해 부여한 것이다 —
  `core/migrations/0001_setup_editor_permissions.py` 참고. 이 마이그레이션
  이전에는 슈퍼유저가 아닌 그룹 사용자가 카테고리를 CRUD할 수 없었다.
- 이미지 권한은 손대지 않았다 — Wagtail이 커스텀 이미지 모델로 스왑해도
  권한 코드네임을 원본 `wagtailimages.Image`에 고정해 두어(Wagtail 소스
  확인) 이미 올바르게 동작한다.
- 2FA는 v1 범위 밖이다(03 §5.1, 기록만 하고 구현하지 않기로 이미 결정됨).

## 6. 로그인 잠금 시 대응

레이트리밋(4절)에 걸리면 15분 뒤 자동으로 풀린다. 급하게 재시도해야 하면
IP가 바뀌는 다른 네트워크(예: 모바일 데이터)로 접속하거나, Render 대시보드
Environment 탭에서 잠시 다른 IP 화이트리스트를 추가하는 등의 절차는 v1에
없다(과설계 방지 — 1인 운영 규모에서 15분 대기는 수용 가능한 트레이드오프로
판단, decisions.md DEC-029).
